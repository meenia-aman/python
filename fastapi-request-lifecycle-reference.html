Uvicorn, Starlette & FastAPI: request lifecycle and exception flow

A reference for what runs, in which order, in which library, and what happens to an exception raised at each point between the socket and your endpoint.

Uvicorn: ASGI server Starlette: ASGI toolkit FastAPI: framework Pydantic: validation engine Your code
Verified, not paraphrased Every ordering and behavior claim here was checked two ways: by reading the installed source of FastAPI 0.162.0, Starlette 1.10.0, Uvicorn 0.54.0 and Pydantic 2.14.3, and by running probe apps that drive the ASGI app directly, the same way Uvicorn's run_asgi() does. The "Verified trace" lines in the diagrams are real output from those probes. Internals move between releases (yield-dependency timing changed in 0.106, 0.110, 0.118 and 0.121), so re-check after upgrades.

Key takeaways

  1. Uvicorn turns socket bytes into an ASGI call, await app(scope, receive, send), and turns send() messages back into bytes. It is also the last safety net: any exception that escapes the app is logged there as Exception in ASGI application.
  2. The real stack, outermost to innermost: ServerErrorMiddleware → ExceptionTelemetryMiddleware → your middleware (the last one added is the outermost) → ExceptionMiddleware → AsyncExitStackMiddleware → Router → APIRoute.
  3. Handlers registered with @app.exception_handler(SomeError) run inside the matched route for errors from dependencies and endpoints, and in ExceptionMiddleware for router 404/405. A handled exception is consumed: it is not re-raised and nobody logs it unless you do.
  4. @app.exception_handler(Exception) (or 500) is different. It is installed on ServerErrorMiddleware, outside your middleware, so its response gets no CORS or request-ID headers. The exception is still re-raised afterwards and Uvicorn logs it. debug=True replaces it with a traceback page.
  5. An exception raised inside middleware never reaches your class-based handlers. Even HTTPException(401) becomes a 500.
  6. Register your HTTP error handler on starlette.exceptions.HTTPException. A handler on fastapi.HTTPException misses the router's 404/405 and FastAPI's own 400 body-parse error.
  7. A yield dependency receives every exception raised after it entered, including RequestValidationError and ResponseValidationError. Always re-raise. Swallowing produces FastAPIError: Response not awaited and a 500.
  8. The default yield-dependency scope is "request": code after yield runs after the response has been sent and after background tasks. A commit there can fail after the client already got a 2xx. Commit inside the use case, or use Depends(dep, scope="function").
  9. pydantic.ValidationError raised by your own code is a 500, not a 422. Only request parsing produces RequestValidationError.
  10. Raise domain exceptions in core code, translate infrastructure exceptions at the repository boundary, roll back in the session dependency, and format every error in one place: global handlers.

1 · Architectural boundaries

1.1 The three layers

The three libraries are separate packages with a strict dependency direction: FastAPI subclasses Starlette, and Starlette knows nothing about Uvicorn. The only contract between the server and the application is the ASGI callable. You could swap Uvicorn for Hypercorn or Granian without touching application code, and you could serve a plain Starlette app with Uvicorn without FastAPI.

Uvicorn

Owns the network and the process. It accepts connections, parses HTTP with an asyncio.Protocol (H11Protocol, HttpToolsProtocol, or the newer zttp implementation, which HTTP/2 requires), builds the scope dict, and starts one task per request: loop.create_task(cycle.run_asgi(app)).

It knows nothing about routes, JSON, or validation.

Starlette

Owns ASGI plumbing. It provides request/response objects, routing, the middleware chain, and the exception machinery: the two built-in middlewares and HTTPException. FastAPI.__call__ delegates to Starlette.__call__, which builds the middleware stack once, on the first request.

It knows nothing about Pydantic or dependency injection.

FastAPI

Owns the developer-facing contract. It reads your function signature to build a Dependant tree, then per request it parses and validates input, resolves dependencies, calls your function, and serializes the result through response_model. It also generates OpenAPI from the same metadata.

FastAPI overrides build_middleware_stack() and ships its own copy of request_response() to add the dependency exit stacks.

1.2 The ASGI contract

ASGI is three things: a scope dict describing the connection, an awaitable receive() that yields incoming messages, and an awaitable send() that accepts outgoing messages. Every middleware in the stack is just another ASGI app that wraps the next one and may wrap receive and send too.

A complete ASGI app, no frameworkpython
async def app(scope, receive, send):
    assert scope["type"] == "http"

    body = b""
    while True:
        message = await receive()      # {"type": "http.request", ...}
        body += message.get("body", b"")
        if not message.get("more_body", False):
            break

    await send({
        "type": "http.response.start",
        "status": 200,
        "headers": [(b"content-type", b"text/plain")],
    })
    await send({
        "type": "http.response.body",
        "body": b"hello",
        "more_body": False,
    })

2 · Request–response lifecycle

2.1 The middleware onion, as actually built

FastAPI overrides Starlette's build_middleware_stack(). It runs once, on the first request, and wraps the router from the inside out. Two details are easy to miss: your middleware sits between the two built-in exception middlewares, and the per-route wrapper adds three more layers that do not appear in any middleware list.

fastapi/applications.py · FastAPI.build_middleware_stack() (abridged)python
for key, value in self.exception_handlers.items():
    if key in (500, Exception):
        error_handler = value               # goes to ServerErrorMiddleware, NOT ExceptionMiddleware
    else:
        exception_handlers[key] = value

middleware = (
    [
        Middleware(ServerErrorMiddleware, handler=error_handler, debug=debug),
        Middleware(ExceptionTelemetryMiddleware),
    ]
    + self.user_middleware                  # add_middleware() inserts at index 0
    + [
        Middleware(ExceptionMiddleware, handlers=exception_handlers, debug=debug),
        Middleware(AsyncExitStackMiddleware),  # closes uploaded files
    ]
)

app = self.router
for cls, args, kwargs in reversed(middleware):
    app = cls(app, *args, **kwargs)         # first item in the list ends up outermost
return app
Ordering rules
  • app.add_middleware(X) inserts at the front of user_middleware, so the last call is the outermost layer. @app.middleware("http") is the same call with BaseHTTPMiddleware.
  • FastAPI(middleware=[A, B]) reads outside-in: A wraps B.
  • Put CORSMiddleware outermost (add it last) so CORS headers land on every response your middleware produces. It still cannot decorate the 500 that ServerErrorMiddleware sends, because that layer is outside all of yours.
  • Verified order for add_middleware(A), add_middleware(B), then @app.middleware("http") C: C → B → A → route.

2.2 Inward path, step by step

Steps a to h follow the request from the socket to your function. The source reference under each title is the function to read if you want to confirm the behavior yourself.

  1. Uvicorn ASGI server entry pointuvicorn/protocols/http/h11_impl.py · H11Protocol.handle_events() → RequestResponseCycle.run_asgi()
    • data_received() feeds bytes to the parser. When the request head is complete, Uvicorn lowercases the headers, splits path and query string, builds scope, creates a RequestResponseCycle, and schedules loop.create_task(cycle.run_asgi(app)). Body chunks keep arriving in the protocol and are handed out through receive(). Reading pauses when the buffer passes the high-water mark (backpressure).
    • app is your FastAPI instance wrapped by ProxyHeadersMiddleware (on by default) and, at --log-level trace, MessageLoggerMiddleware.
    • FastAPI.__call__ applies root_path, sends lifespan scopes to the lifespan handler, opens an OpenTelemetry server span if a provider is configured, then calls Starlette.__call__. That sets scope["app"] and builds the middleware stack on first use. From then on add_middleware() raises RuntimeError("Cannot add middleware after an application has started").
    Fails here: malformed HTTP → Uvicorn 400; limit_concurrency reached → Uvicorn 503. The app never runs, so none of your handlers or middleware can see these.
  2. ServerErrorMiddleware: outermost catch-allstarlette/middleware/errors.py · ServerErrorMiddleware.__call__()
    • Wraps send to record whether http.response.start has gone out, then runs try: await self.app(scope, receive, _send) with except Exception.
    • On a healthy request it does nothing else. Its job starts when an exception reaches it; see 3.5.
    • FastAPI puts ExceptionTelemetryMiddleware directly inside it. That layer records the exception on the current span and re-raises; it never produces a response.
  3. Your middleware: @app.middleware("http"), BaseHTTPMiddleware, pure ASGIstarlette/applications.py · add_middleware() · starlette/middleware/base.py · BaseHTTPMiddleware.__call__()
    • Runs outermost-first, as described in the ordering rules above.
    • BaseHTTPMiddleware wraps the request in a _CachedRequest, then your dispatch(request, call_next) runs. call_next() starts the rest of the app in a separate AnyIO task and returns a Response as soon as the inner app sends http.response.start. The body streams through a memory channel.
    • Pure ASGI middleware calls await self.app(scope, receive, send) in the same task, and can wrap receive and send.
    Fails here: anything raised in middleware code, including HTTPException, skips ExceptionMiddleware (it is further in) and ends at ServerErrorMiddleware → 500.
  4. ExceptionMiddleware: publishes the handler registrystarlette/middleware/exceptions.py · ExceptionMiddleware.__call__() · starlette/_exception_handler.py
    • Writes scope["starlette.exception_handlers"] = (class_handlers, status_handlers). It contains everything in app.exception_handlers except the Exception and 500 keys. FastAPI pre-registers handlers for StarletteHTTPException, RequestValidationError and WebSocketRequestValidationError with setdefault, so registering your own for the same class replaces the default.
    • Wraps the router in wrap_app_handling_exceptions(). This instance handles exceptions raised by the router itself (404, 405) and by anything between it and the route. Exceptions from inside a route are handled one level deeper, by the route's own wrapper (step e), using the same registry. The behavior is the same; the location matters only for what has already been cleaned up.
    • Just inside it, FastAPI's AsyncExitStackMiddleware opens scope["fastapi_middleware_astack"], used to close uploaded files and form data.
  5. Router and APIRoute matchingstarlette/routing.py · Router.app() · fastapi/routing.py · APIRoute.matches(), APIRoute.handle(), request_response()
    • The router iterates its routes in order. route.matches(scope) returns FULL (path and method), PARTIAL (path only) or NONE. The first FULL wins and adds endpoint, path_params and route to the scope. Declaration order matters: /users/me must come before /users/{user_id}.
    • No FULL but a PARTIAL → HTTPException(405) with an Allow header. Nothing at all → trailing-slash redirect check (307), then HTTPException(404).
    • APIRoute.app is request_response(handler). Per request it wraps the handler in wrap_app_handling_exceptions(app, request) and opens two exit stacks: request_stack around the handler and the response sending, and function_stack around the handler only.
  6. FastAPI dependency injection: Depends, including yield setupfastapi/routing.py · get_request_handler() · fastapi/dependencies/utils.py · solve_dependencies(), _solve_generator()
    • The body is read first. get_request_handler() awaits request.body() and calls request.json() when the Content-Type is JSON. With strict_content_type=True (the default), a body without a JSON content type is not parsed as JSON. Forms go through request.form(). Invalid JSON raises RequestValidationError (type json_invalid) here, before any dependency runs. Other read failures raise HTTPException(400).
    • solve_dependencies() walks the Dependant tree depth-first, in declaration order. For each dependency it solves that dependency's own sub-dependencies and parameters, then calls it:
      • async def → awaited on the event loop. def → run_in_threadpool.
      • Generator (yield) → wrapped in asynccontextmanager (or contextmanager_in_threadpool for sync generators) and entered on request_stack, or on function_stack when declared with scope="function". The code up to yield runs now.
      • Results are cached per request (key: callable plus security scopes) unless use_cache=False. A dependency shared by five others runs once.
      • app.dependency_overrides are substituted at this point.
    Fails here: a dependency that raises stops resolution. Later dependencies and the endpoint never run. Yield dependencies that already entered receive the exception at their yield when the exit stacks unwind.
  7. Request parsing and Pydantic validation → RequestValidationErrorfastapi/dependencies/utils.py · request_params_to_args(), request_body_to_args()
    • Each dependant's own path, query, header, cookie and body parameters are validated by Pydantic after its sub-dependencies have been resolved. Errors are collected, not raised. A dependency whose parameters fail is skipped; independent dependencies still run.
    • When the whole tree is solved and the error list is not empty, FastAPI raises RequestValidationError(errors, body=...). So steps f and g are interleaved, and yield dependencies that already entered see the RequestValidationError. Verified trace: db:setup → db:rollback(RequestValidationError) → db:close → 422.
    • Default handler: 422 with {"detail": jsonable_encoder(exc.errors())}. Each error has type, loc (starting with "body", "query", "path", "header" or "cookie"), msg and input.
  8. Endpoint execution and response-model serializationfastapi/routing.py · run_endpoint_function(), serialize_response(), _build_response_args()
    • async def endpoints are awaited on the event loop. def endpoints run in the AnyIO thread pool (40 threads by default). A blocking call inside an async def stalls every request on that worker.
    • If the endpoint returns a Response, FastAPI uses it as-is and attaches the request's background tasks. Otherwise it validates the value against response_model (or the return annotation). Failure → ResponseValidationError → 500, because it is a server bug.
    • With a response model and the default response class, Pydantic's serialize_json writes JSON bytes directly into a Response, skipping the dict-then-json.dumps step. Without a model, FastAPI uses jsonable_encoder and JSONResponse.
    • Status code: the decorator's status_code, overridden by the status_code of an injected Response parameter. Headers set on the injected Response are merged in. Bodies are emptied for 1xx, 204, 205 and 304.
    • Generator endpoints (server-sent events, JSON Lines, StreamingResponse) skip this step; items are validated and serialized while they stream.
    Fails here: any exception from your code propagates out through function_stack, then request_stack (yield dependencies run their except/finally blocks), then reaches the route's wrap_app_handling_exceptions.

2.3 Outward path

  1. Function-scoped teardownfastapi/routing.py · request_response() · function_stack.__aexit__

    As soon as the handler returns a Response object, function_stack closes: code after yield in scope="function" dependencies runs. Nothing has been sent yet, so an exception here can still become a proper error response.

  2. await response(scope, receive, send)starlette/responses.py · Response.__call__()

    Sends http.response.start then http.response.body, then awaits self.background(). Background tasks run in the same request task, after the body has been sent.

  3. Messages travel back up through every send wrapperroute sender → ExceptionMiddleware sender → your middleware → ServerErrorMiddleware._send → Uvicorn send()

    Pure ASGI middleware can rewrite headers in the http.response.start message. In BaseHTTPMiddleware, the messages go into a memory stream, call_next() returns a response object, and your dispatch may edit response.headers before the middleware forwards it. The inner app's final body message waits until the outer response has been sent.

  4. Uvicorn writes the bytesuvicorn/protocols/http/h11_impl.py · RequestResponseCycle.send()

    On http.response.start: prepends default headers (server, date), writes the access-log line, writes the status line and headers. On the final body chunk: ends the message, then keeps the connection alive or closes it.

  5. Request-scoped teardownfastapi/routing.py · request_response() · request_stack.__aexit__

    After the response has been sent and background tasks have finished, request_stack closes: code after yield in default-scope dependencies runs, in reverse order of setup (LIFO). The client already has the full response.

  6. The call stack unwindsuvicorn · RequestResponseCycle.run_asgi()

    Each layer returns None. Uvicorn checks the result: returned without starting a response → logs an error and sends 500; returned without finishing the body → closes the connection.

Anatomy of a yield dependencypython
async def get_session(request: Request) -> AsyncIterator[AsyncSession]:
    # (1) SETUP: runs during solve_dependencies(), before the endpoint.
    #     An exception here behaves like one from a normal dependency:
    #     the endpoint never runs and later dependencies are skipped.
    async with request.app.state.session_factory() as session:
        try:
            # (2) YIELD: the value is injected. The endpoint runs now.
            yield session
            # (3) SUCCESS PATH: runs at teardown if nothing was raised.
            #     Default scope -> after the response was sent. Do not commit here
            #     unless the dependency is declared with scope="function".
        except Exception:
            # (4) FAILURE PATH: any exception raised after (2) is thrown in here:
            #     endpoint errors, HTTPException, RequestValidationError,
            #     ResponseValidationError, errors from later dependencies.
            await session.rollback()
            raise  # (5) ALWAYS re-raise (or raise a translated exception).
        # (6) FINALLY: `async with` closes the session on every path.

Resolution order example

async def db(): ...                       # yield
async def current_user(s=Depends(db)): ...
async def audit(s=Depends(db)): ...       # yield

@app.post("/orders")
async def create(user=Depends(current_user),
                 a=Depends(audit),
                 body: OrderIn = Body()): ...

Setup: db → current_user → audit (reuses cached db) → validate body → endpoint. Teardown is LIFO: audit → db. If body is invalid, db and audit have already entered and receive the RequestValidationError.

Rules that follow from the code

  • Declaration order is execution order. Put cheap rejections (auth, rate limits) first so expensive dependencies are skipped when they fail.
  • Path/query/header/cookie validation of the endpoint's parameters happens after all dependencies ran. If a dependency must not run on invalid input, give it those parameters itself.
  • A sync (def) yield dependency runs setup and teardown in the thread pool.
  • use_cache=False forces a fresh call each time the dependency is declared.
  • Swallowing an exception in except without re-raising leaves FastAPI with no response. You get FastAPIError: Response not awaited (request scope) or UnboundLocalError (function scope). Both are 500s.

3.1 The catch points and the handler lookup

What the lookup implies

  • MRO walk. A handler for DomainError catches every subclass. The most specific registered class wins, so you can add a handler for one subclass later without touching the base handler.
  • Status handlers first. @app.exception_handler(404) applies to any HTTPException with status 404, including the router's. Verified: it caught both GET /missing and a raised HTTPException(404).
  • Exception and 500 are special keys. build_middleware_stack() moves them to ServerErrorMiddleware. They are never in the registry, so the MRO walk never reaches them.
  • Return a Response. A handler that returns None sends nothing; Uvicorn then logs ASGI callable returned without starting response and answers 500 itself (verified: nothing was sent).

What "handled" means for logging

  • A handled exception stops. No middleware sees it as an exception and Uvicorn does not log it. If a 409 or a 503 matters to you, log it in the handler.
  • An unhandled exception is logged once by Uvicorn (Exception in ASGI application with the traceback), because ServerErrorMiddleware re-raises after responding. If your Exception handler also logs the traceback, you get it twice.
  • If a handler itself raises, the new exception continues outward and ends in ServerErrorMiddleware (verified: AttributeError from a handler → 500).
  • Starlette's TestClient re-raises server exceptions by default for the same reason. Use TestClient(app, raise_server_exceptions=False) to assert on the 500 body.

Domain exceptions vs infrastructure exceptions

Domain / business exceptions

OrderNotFound, InsufficientStock, EmailAlreadyRegistered, PermissionDenied

  • Expected outcomes, part of the business vocabulary. They mean "the request cannot be fulfilled as asked."
  • Raised by entities, domain services and use cases. Plain Python classes: no FastAPI, no status codes.
  • Mapped to 4xx in one place, the presentation layer's handlers.
  • Usually not worth a traceback. Log at INFO or not at all.

Infrastructure exceptions

sqlalchemy.exc.IntegrityError, OperationalError, httpx.TimeoutException, redis.ConnectionError

  • Technical failures of a collaborator, named in a vendor's vocabulary.
  • Some carry domain meaning: a unique-constraint violation on users.email is "email already registered". Translate those inside the repository, where the constraint is known: raise EmailAlreadyRegistered(...) from exc.
  • The rest are transient or unexpected: connection refused, timeout, deadlock. Let them propagate. Map the known transient ones to 503 with Retry-After in a handler; leave everything else as 500.
  • Always chain with from exc so the original cause stays in the traceback.

Unhandled Exception, and framework errors to recognize

Anything without a matching handler is "unhandled": bugs, unmapped infrastructure errors, errors in middleware, errors after the response started. It always ends at ServerErrorMiddleware, which produces a 500 if nothing was sent and then re-raises so Uvicorn logs the traceback. BaseException subclasses (asyncio.CancelledError, KeyboardInterrupt, SystemExit) skip every Starlette handler, because they all catch Exception.

3.6 Where to catch: architectural rules

The question for every try is: can this layer do something specific about this specific exception? Valid answers are recover, clean up, translate into a more meaningful exception, or format it for the client. If the answer is "log it and return something", let it propagate.

Repositoryinfrastructure

Catch specific driver or ORM exceptions that carry domain meaning, and translate them: unique violation on uq_users_email → EmailAlreadyRegistered; NoResultFound → UserNotFound. Use raise DomainError(...) from exc. Call await session.flush() inside the repository method so constraint violations surface there, where you still know which constraint it was, instead of at commit time somewhere else.

Don't catch Exception or bare SQLAlchemyError, return None to signal failure, commit, or raise HTTPException.

Use case / serviceapplication

Raise domain exceptions for rule violations. Own the transaction boundary: call uow.commit() as the last step. Catch only to recover or compensate: retry an optimistic-lock conflict, call a fallback provider, undo a side effect in another system.

Don't import FastAPI, raise HTTPException, or pick status codes. The same use case should work from a CLI, a worker, or a test.

Yield dependencyresource lifecycle

Catch Exception to roll back, then re-raise. Clean up in finally or async with. If the dependency commits on success, declare it with scope="function" so a commit failure can still become an error response; translating a commit-time IntegrityError into a domain exception there is fine.

Don't swallow exceptions, return error responses, or commit after yield in the default request scope (the client already has a 2xx, and a failing background task turns your commit into a rollback after the fact).

Route handlerpresentation

Let exceptions propagate. A route maps HTTP input to a use-case call and the result to a response model. Catch only a specific exception that has a different valid outcome for this route, for example an idempotent create that returns the existing resource on AlreadyExists.

Don't wrap the body in try/except Exception (see 3.7).

Global handlersedge / composition root

Register one handler per category: DomainError (status from a mapping), StarletteHTTPException, RequestValidationError, selected transient infrastructure errors (e.g. OperationalError → 503 + Retry-After), and Exception as the last resort. All of them emit the same error schema.

Don't put business logic, DB calls or retries in handlers. Keep them pure formatting plus logging.

Middlewarecross-cutting

Use for request IDs, access logging, timing, and optionally an inner catch-all that formats unexpected errors inside CORS. When you reject a request in middleware, return a Response.

Don't raise HTTPException or domain exceptions from middleware. They become 500s.

What goes wrong with the left version, mechanically:

  1. The yield dependency never sees the exception. The route returned normally, so TxSession takes its success path and commits. If the failure came after some rows were flushed (a domain check, a bug, a call to another service), those rows are committed: a half-created order is persisted.
  2. Wrong status codes. A missing product (should be 404), a conflict (409), a database outage (503) and a KeyError (500) all become 400. Clients, retry logic, load balancers and alerting all act on the wrong signal.
  3. Lost observability. Uvicorn never logs a traceback, so 5xx dashboards stay green while bugs happen.
  4. The plain-dict variant is worse. Returning {"error": ...} instead of a JSONResponse fails response_model=OrderOut validation, so the client gets a 500 from ResponseValidationError and the original error is hidden behind it.
  5. Information leak. str(exc) can contain SQL, table names, file paths, or hostnames.
  6. Inconsistency. Every route invents its own error shape, and none of it appears in the OpenAPI schema.

from __future__ import annotations

from collections.abc import Mapping
from typing import Any, ClassVar


class DomainError(Exception):
    """Base class for expected business-rule failures."""

    code: ClassVar[str] = "DOMAIN_ERROR"
    default_message: ClassVar[str] = "The request violates a business rule."

    def __init__(self, message: str | None = None, **context: Any) -> None:
        self.message = message or self.default_message
        self.context: Mapping[str, Any] = context  # structured data for logs, never shown raw
        super().__init__(self.message)


class NotFoundError(DomainError):
    code = "NOT_FOUND"
    default_message = "The requested resource does not exist."


class ConflictError(DomainError):
    code = "CONFLICT"
    default_message = "The request conflicts with the current state of the resource."


class PermissionDeniedError(DomainError):
    code = "PERMISSION_DENIED"
    default_message = "You are not allowed to perform this action."


class BusinessRuleViolation(DomainError):

4.3 Repository: translate infrastructure errors that carry domain meaning

from sqlalchemy.exc import IntegrityError

UNIQUE_VIOLATION = "23505"       # PostgreSQL SQLSTATE codes
FOREIGN_KEY_VIOLATION = "23503"


def sqlstate(exc: IntegrityError) -> str | None:
    # SQLAlchemy's asyncpg adapter and psycopg 3 both expose .sqlstate on exc.orig.
    return getattr(exc.orig, "sqlstate", None)


def is_unique_violation(exc: IntegrityError, constraint: str | None = None) -> bool:
    if sqlstate(exc) != UNIQUE_VIOLATION:
        return False
    # PostgreSQL names the constraint in the message:
    # duplicate key value violates unique constraint "uq_users_email"
    return constraint is None or constraint in str(exc.orig)
app/modules/users/infrastructure/repositories.pypython
from uuid import UUID

from sqlalchemy import exists, select
from sqlalchemy.exc import IntegrityError
from sqlalchemy.ext.asyncio import AsyncSession

from app.core.db_errors import is_unique_violation
from app.modules.users.domain.entities import User
from app.modules.users.domain.exceptions import EmailAlreadyRegistered, UserNotFound
from app.modules.users.infrastructure.models import UserRow


class SqlAlchemyUserRepository:
    def __init__(self, session: AsyncSession) -> None:
        self._session = session

    async def get(self, user_id: UUID) -> User:
        row = await self._session.get(UserRow, user_id)
        if row is None:
            raise UserNotFound(user_id=str(user_id))
        return row.to_entity()

    async def exists_by_email(self, email: str) -> bool:
        stmt = select(exists().where(UserRow.email == email))
        return bool(await self._session.scalar(stmt))

    async def add(self, user: User) -> None:
        self._session.add(UserRow.from_entity(user))
        try:
            # Flush here so constraint violations surface in the method that
            # knows which constraint means what, not later at commit time.
            await self._session.flush()
        except IntegrityError as exc:
            if is_unique_violation(exc, constraint="uq_users_email"):
                raise EmailAlreadyRegistered(email=user.email) from exc
            raise  # an unexpected constraint is a bug: let it become a 500
        # The session is now unusable until rolled back; get_session() does that
        # when the exception passes through it.

from app.modules.users.domain.entities import User
from app.modules.users.domain.exceptions import EmailAlreadyRegistered


class RegisterUser:
    def __init__(self, uow: UnitOfWork, hasher: PasswordHasher) -> None:
        self._uow = uow
        self._hasher = hasher

    async def execute(self, *, email: str, password: str) -> User:

            raise EmailAlreadyRegistered(email=email)  # common case: cheap check first

        user = User.register(email=email, password_hash=self._hasher.hash(password))
        await self._uow.users.add(user)  # race case: the repository translates the unique violation
        await self._uow.commit()         # the use case owns the transaction; runs before any response exists
        return user

from http import HTTPStatus

from fastapi import FastAPI, Request
from fastapi.exceptions import RequestValidationError
from fastapi.responses import JSONResponse, Response
from sqlalchemy.exc import OperationalError
from starlette.exceptions import HTTPException as StarletteHTTPException  # NOT fastapi.HTTPException

from app.core.error_schemas import PROBLEM_JSON, FieldError, ProblemDetail
from app.core.errors import (
    BusinessRuleViolation,
    ConflictError,
    DomainError,
    NotFoundError,
    PermissionDeniedError,
)

logger = logging.getLogger("app.errors")

# Status codes live at the edge. Lookup walks the MRO, so subclasses inherit a mapping.
DOMAIN_STATUS: dict[type[DomainError], int] = {
    NotFoundError: 404,
    ConflictError: 409,
    PermissionDeniedError: 403,
    BusinessRuleViolation: 422,
}


def status_for(exc: DomainError) -> int:
    for cls in type(exc).__mro__:
        if cls in DOMAIN_STATUS:
            return DOMAIN_STATUS[cls]
    return 400


def _title(status: int) -> str:
    try:
        return HTTPStatus(status).phrase
    except ValueError:
        return "Error"


def problem_response(
    request: Request,
    *,
    status: int,
    code: str,
    detail: str | None = None,
    errors: list[FieldError] | None = None,
    headers: Mapping[str, str] | None = None,
) -> JSONResponse:
    body = ProblemDetail(
        title=_title(status),
        status=status,
        detail=detail,
        instance=request.url.path,
        code=code,
        request_id=getattr(request.state, "request_id", None),
        errors=errors,
    )
    return JSONResponse(
        body.model_dump(mode="json", exclude_none=True),
        status_code=status,
        headers=dict(headers or {}),
        media_type=PROBLEM_JSON,
    )


def register_exception_handlers(app: FastAPI) -> None:
    # Runs in the route wrapper: inside your middleware, after yield-dependency cleanup.
    @app.exception_handler(DomainError)
    async def handle_domain_error(request: Request, exc: DomainError) -> JSONResponse:
        status = status_for(exc)
        logger.info("domain_error code=%s status=%s path=%s", exc.code, status, request.url.path)
        return problem_response(request, status=status, code=exc.code, detail=exc.message)

    # A known transient infrastructure failure. Handled = not logged by Uvicorn, so log it here.
    @app.exception_handler(OperationalError)
    async def handle_db_unavailable(request: Request, exc: OperationalError) -> JSONResponse:
        logger.warning("database_unavailable path=%s", request.url.path, exc_info=exc)
        return problem_response(
            request,
            status=503,
            code="DEPENDENCY_UNAVAILABLE",
            detail="A backing service is temporarily unavailable. Retry later.",
            headers={"Retry-After": "5"},
        )

    # Catches fastapi.HTTPException too (subclass), plus router 404/405 and body-parse 400.
    @app.exception_handler(StarletteHTTPException)
    async def handle_http_exception(request: Request, exc: StarletteHTTPException) -> Response:
        if exc.status_code in (204, 304):
            return Response(status_code=exc.status_code, headers=exc.headers)
        detail = exc.detail if isinstance(exc.detail, str) else _title(exc.status_code)
        return problem_response(
            request,
            status=exc.status_code,
            code=f"HTTP_{exc.status_code}",
            detail=detail,
            headers=exc.headers,  # keeps Allow, WWW-Authenticate, Retry-After
        )

    # Replaces FastAPI's default 422 handler. Drops `input` and `ctx` so submitted
    # values (passwords, tokens) are never echoed back.
    @app.exception_handler(RequestValidationError)
    async def handle_request_validation(request: Request, exc: RequestValidationError) -> JSONResponse:
        errors = [
            FieldError(loc=list(err["loc"]), message=err["msg"], type=err["type"])
            for err in exc.errors()
        ]
        return problem_response(
            request, status=422, code="VALIDATION_FAILED", detail="The request is invalid.", errors=errors
        )

    # Last resort. Installed on ServerErrorMiddleware: runs OUTSIDE your middleware,
    # and the exception is re-raised afterwards, so Uvicorn logs the traceback.
    # Log context only here to avoid a second traceback.
    @app.exception_handler(Exception)
    async def handle_unexpected(request: Request, exc: Exception) -> JSONResponse:
        logger.error("unhandled_exception type=%s path=%s", type(exc).__name__, request.url.path)
        response = problem_response(
            request, status=500, code="INTERNAL_ERROR", detail="An unexpected error occurred."
        )
        request_id = getattr(request.state, "request_id", None)
        if request_id:  # RequestIdMiddleware cannot add it: this response bypasses it
            response.headers["X-Request-ID"] = request_id
        return response
Why request.state.request_id works in every handlerrequest.state is backed by scope["state"], and all layers share one scope dict. Once RequestIdMiddleware writes the ID into it, even ServerErrorMiddleware, which builds a fresh Request(scope), can read it.

4.7 Middleware: request IDs and a CORS-friendly catch-all

app/core/middleware.pypython
import logging
import re
import uuid

from fastapi.responses import JSONResponse
from starlette.datastructures import Headers, MutableHeaders
from starlette.types import ASGIApp, Message, Receive, Scope, Send

from app.core.error_schemas import PROBLEM_JSON, ProblemDetail

logger = logging.getLogger("app.errors")

# The incoming header is untrusted input: accept only short, safe IDs.
_REQUEST_ID_RE = re.compile(r"^[A-Za-z0-9._-]{1,128}$")


class RequestIdMiddleware:
    """Pure ASGI: same task as the app, no body buffering, works with streaming."""

    def __init__(self, app: ASGIApp, header_name: str = "x-request-id") -> None:
        self.app = app
        self.header_name = header_name

    async def __call__(self, scope: Scope, receive: Receive, send: Send) -> None:
        if scope["type"] != "http":
            await self.app(scope, receive, send)
            return

        incoming = Headers(scope=scope).get(self.header_name)
        request_id = incoming if incoming and _REQUEST_ID_RE.match(incoming) else uuid.uuid4().hex
        scope.setdefault("state", {})["request_id"] = request_id  # visible as request.state.request_id

        async def send_with_request_id(message: Message) -> None:
            if message["type"] == "http.response.start":
                MutableHeaders(scope=message).append(self.header_name, request_id)
            await send(message)

        await self.app(scope, receive, send_with_request_id)


class UnhandledExceptionMiddleware:
    """Formats unexpected errors INSIDE CORS / request-ID middleware.

    ServerErrorMiddleware's 500 bypasses every user middleware, so browsers see a
    CORS failure instead of the error. Added before CORSMiddleware (so it sits
    inside it), this layer answers first and the outer layers decorate the response.
    Trade-off: the exception stops here, so it must log the traceback itself, and
    debug=True tracebacks no longer appear.
    """

    def __init__(self, app: ASGIApp) -> None:
        self.app = app

    async def __call__(self, scope: Scope, receive: Receive, send: Send) -> None:
        if scope["type"] != "http":
            await self.app(scope, receive, send)
            return

        response_started = False

        async def tracking_send(message: Message) -> None:
            nonlocal response_started
            if message["type"] == "http.response.start":
                response_started = True
            await send(message)

        try:
            await self.app(scope, receive, tracking_send)
        except Exception:
            if response_started:
                raise  # too late to change the status; let ServerErrorMiddleware and Uvicorn log it
            logger.exception("unhandled_exception path=%s", scope.get("path"))
            body = ProblemDetail(
                title="Internal Server Error",
                status=500,
                detail="An unexpected error occurred.",
                instance=scope.get("path"),
                code="INTERNAL_ERROR",
                request_id=scope.get("state", {}).get("request_id"),
            )
            response = JSONResponse(
                body.model_dump(mode="json", exclude_none=True),
                status_code=500,
                media_type=PROBLEM_JSON,
            )
            await response(scope, receive, send)

app/main.pypython
from collections.abc import AsyncIterator
from contextlib import asynccontextmanager

from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
from sqlalchemy.ext.asyncio import async_sessionmaker, create_async_engine

from app.core.exception_handler import register_exception_handlers
from app.core.middleware import RequestIdMiddleware, UnhandledExceptionMiddleware
from app.core.settings import settings
from app.modules.users.presentation.routers import router as users_router


@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    # An exception here aborts startup: Uvicorn logs "Application startup failed. Exiting."
    engine = create_async_engine(settings.database_url, pool_pre_ping=True)
    app.state.session_factory = async_sessionmaker(engine, expire_on_commit=False)
    try:
        yield
    finally:
        await engine.dispose()


def create_app() -> FastAPI:
    app = FastAPI(title="Users API", lifespan=lifespan, debug=False)

    register_exception_handlers(app)

    # add_middleware() inserts at the front: the LAST call is the OUTERMOST layer.
    # Resulting order: ServerError → Telemetry → CORS → RequestId → Unhandled → ExceptionMiddleware → routes
    app.add_middleware(UnhandledExceptionMiddleware)  # innermost of ours: catches bugs first
    app.add_middleware(RequestIdMiddleware)           # its header lands on the 500 above
    app.add_middleware(                               # outermost: CORS headers on every response
        CORSMiddleware,
        allow_origins=settings.cors_origins,
        allow_methods=["*"],
        allow_headers=["*"],
        expose_headers=["X-Request-ID"],
    )

    app.include_router(users_router, prefix="/api/v1")
    return app


app = create_app()

With this order the Exception handler from 4.6 is still useful: it covers errors raised by CORSMiddleware or RequestIdMiddleware themselves, which are outside the catch-all. If you would rather keep Uvicorn's traceback logging and the debug page, drop UnhandledExceptionMiddleware and accept that 500s carry no CORS headers.

Registration recipe

@app.exception_handler(DomainError)             # 4xx from a mapping
@app.exception_handler(StarletteHTTPException)  # NOT fastapi.HTTPException
@app.exception_handler(RequestValidationError)  # 422, sanitized errors
@app.exception_handler(OperationalError)        # 503 + Retry-After, log it
@app.exception_handler(Exception)               # last resort, runs outside middleware

app.add_middleware(RequestIdMiddleware)
app.add_middleware(CORSMiddleware, ...)           # added last = outermost

Decision rules

  • Can this layer recover, clean up, or translate? Catch that specific exception. Otherwise let it propagate.
  • Is the exception named after a vendor (SQLAlchemy, httpx, redis)? If it has domain meaning, translate it in the repository with from exc. If not, let it propagate to a handler or to the 500 path.
  • In a yield dependency? Roll back or release, then re-raise.
  • In a route? Do not catch.
  • In middleware? Return a Response; never raise for control flow.
  • Has http.response.start been sent? Then nothing can change the status code. Validate before you start streaming, and commit before the response exists.

"""Drive an ASGI app directly, the way Uvicorn's run_asgi() does. No server, no HTTP client."""

import asyncio


async def call(app, method="GET", path="/", body=b"", headers=()):
    scope = {
        "type": "http",
        "asgi": {"version": "3.0", "spec_version": "2.3"},
        "http_version": "1.1",
        "method": method,
        "scheme": "http",
        "path": path,
        "raw_path": path.encode(),
        "query_string": b"",
        "root_path": "",
        "headers": [(b"host", b"test"), *headers],
        "client": ("127.0.0.1", 1),
        "server": ("test", 80),
        "state": {},
    }
    sent: list[dict] = []
    done = asyncio.Event()
    pending = [{"type": "http.request", "body": body, "more_body": False}]

    async def receive():
        if pending:
            return pending.pop(0)
        await done.wait()  # like Uvicorn: disconnect only after the response is complete
        return {"type": "http.disconnect"}

    async def send(message):
        sent.append(message)
        if message["type"] == "http.response.body" and not message.get("more_body", False):
            done.set()

    escaped = None
    try:
        await app(scope, receive, send)
    except BaseException as exc:  # exactly what Uvicorn catches and logs
        escaped = exc

    start = next((m for m in sent if m["type"] == "http.response.start"), None)
    status = start["status"] if start else None
    body_out = b"".join(m.get("body", b"") for m in sent if m["type"] == "http.response.body")
    return status, body_out, escaped
